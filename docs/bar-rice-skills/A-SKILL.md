## 0. 环境与硬约束

- 工作目录：`<repo-root>`
- 设备：`emulator-5554`，release 包 `io.github.blancatora.orionekox`（当前 0.8.103，
  versionCode 1189），debug 包为 `.debug`；以 release 为准。
- 只与本地智能体（界面标注“本地智能体”）或仅含本地成员的群交互。
- **禁止**给真实 Telegram 联系人发消息；**禁止** `pm clear`、删除用户数据、改真实账号设置；
  **禁止**读取或输出 API Key、手机号、私有邮箱；不要 `git commit`/`git push`。

- 如无障碍失效，可执行：
  `adb shell settings put secure enabled_accessibility_services io.github.blancatora.orionekox/org.telegram.ox.OxAccessibilityService`

## 1. 全流程（必须全部执行）

### 1.1 基线
1. 启动 app，确认聊天列表/底部 聊天、联系人、设置、我的、终端 五个 Tab 可见。
2. `adb logcat -c` 清空日志，记录 versionName/versionCode。
3. 截图基线到 `/tmp/bar-rice-A/00-home.png`。

### 1.2 建立测试 Agent
1. 进入 联系人（或 Ox 设置 → 智能体），新建一个本地智能体，命名
   `酒吧炒饭A`，简介写“深夜酒吧炒饭主厨”。
2. 系统提示词：`你是「酒吧炒饭」深夜主厨。中文回答，先确认忌口，再给 15 分钟单锅配方。`
3. Provider/模型选择当前已配置且可用的一个（参考 Yuki 的配置）；不要打开或抄写密钥。
4. 保存，确认新 Agent 出现在联系人列表和聊天列表；截图。
5. 若编辑器要求头像/用户名，保持默认或使用本地生成的纯色图，不要上传隐私图片。

### 1.3 单聊、记忆与工作区
1. 打开 `酒吧炒饭A` 单聊，发送：
   `我在酒吧后厨，只有一口锅、隔夜米饭、2 个鸡蛋、葱、酱油、油。做两人份酒吧炒饭。先记住：我不吃香菜。给出步骤。`
2. 等待真实模型回复；确认不是固定模板/报错，记录回复要点和耗时；截图。
3. 发送：`把配方保存到工作区文件 bar-fried-rice.md，并在回复里告诉我路径。`
4. 打开该 Agent 的工作区/文件页面，确认 `bar-fried-rice.md` 存在且内容为炒饭步骤；
   若工具调用需要确认，选择允许并记录权限提示文案。
5. 新开一轮发送：`我忌口什么？只回答忌口。` 确认能回忆“不吃香菜”；截图。
6. 返回聊天列表，再进入该 Agent，确认会话与记忆仍在（不重启 app）。

### 1.4 媒体
1. 用本机 Python/PIL 生成一张 640×480、带 `BAR FRIED RICE` 文字的 JPEG，
   `adb push` 到 `/sdcard/Download/bar-rice-A.jpg`。
2. 在单聊里用附件/相册发送该图片；确认发出后气泡正常显示缩略图，无 X、0KB、
   下载箭头或红叹号；截图。
3. 长按该图片消息，确认菜单出现（复制/转发/删除等），仅查看后返回，不执行删除。

### 1.5 本地群、成员与群回复
1. 从聊天列表新建群组，选择 `酒吧炒饭A` 与 Yuki Waifu 两个本地智能体，
   命名 `酒吧炒饭A测试群`，创建。
2. 打开群资料页，确认成员数与成员行正确（TestUser 创建者 + 两个 agent）；截图。
3. 在群里发送：`群里确认：两人份炒饭要不要加香菜？各自用一句话回答。`
   等待本地 agent 回复，确认群内出现回复气泡且没有红叹号；截图。
4. 群资料页 → 添加成员 → 选择 Echo Assistant → 确认；确认成员数 +1 且 Echo 只有一行。
5. 长按 Echo 成员行 → 从群组中移除；确认成员数立即恢复、Echo 消失。
6. 长按群内一条消息，确认菜单出现；仅查看后返回。

### 1.6 设置与扩展抽查
1. 打开 设置 → Ox 设置，逐项查看（不要改开关/单选）：模式、语言、本地会员、
   引导与授权、智能体、MCP 服务、工具与权限、技能库、工作区。
2. 打开 MCP 服务页，查看列表与详情/新增入口，不保存任何改动。
3. 打开技能库，点开示例技能，确认 SKILL.md 预览可滚动、可关闭。
4. 打开底部 终端，切换 TTY 1/2/3，各执行 `pwd`（或 `echo ok`），确认输出与标签正常。
5. 打开 设置 → 代理与 VPN（若入口可见），只读查看各分区。
6. 检查机器翻译/乱码/重复图标/文案不通顺，记录页面与原文。

### 1.7 崩溃、清理与报告
1. `adb logcat -d | grep -E "FATAL EXCEPTION|ANR in io.github.blancatora.orionekox"`，
   记录是否有崩溃。
2. 不删除用户数据；测试 Agent/群可保留，在报告中写清名称，供主代理清理。
3. 写 `docs/bar-rice-test-A.md`，必须包含：
   - 版本、设备、开始/结束时间；
   - 每一步 PASS/FAIL 与证据（截图路径、关键 logcat 行）；
   - 发现的问题：复现步骤、期望/实际、严重级别（P0/P1/P2）；
   - 文案/翻译/UI 原生规范问题；
   - 未执行项及原因（没有就写“无”）；
   - 最终结论：是否通过全流程。
