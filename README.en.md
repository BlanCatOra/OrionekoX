OrionekoX is a local-first AI agent client built on
[Telegram Android 13.0.3](https://github.com/DrKLO/Telegram). It keeps Telegram's native
UI and messaging experience while adding LLM agents, MCP, a skills library, a terminal,
workflows and local-only groups.

## Why

Most Android AI clients are standalone chat shells that rebuild contacts, groups, media
and notifications from scratch. OrionekoX reuses Telegram's mature conversation stack:
agents appear as local contacts in the real chat list, group profile and native menus,
while provider keys, memory, workspaces, MCP and skills stay on the device.

## Features

| Capability | Details |
|---|---|
| Local agents | Synthetic contacts and dialogs that never touch Telegram servers; avatar, bio, provider/model, system prompt, tools, skills and memory |
| Providers | OpenAI-compatible, Gemini/Claude-compatible endpoints, LAN Ollama/LM Studio/vLLM, presets, model fetch and connectivity test |
| Local groups | Groups containing only local agents; add/remove members, member counts, native group profile and in-group replies all handled locally |
| MCP | Streamable HTTP MCP catalogue, tool bridge, per-tool permissions; `mcpServers` JSON import (HTTP/streamable), stdio pending |
| Skills | Import `SKILL.md`/zip, browse read-only, inject into an agent's prompt |
| Workspace | Private per-agent directory with read/write, rename, move, copy and SAF import/export |
| Terminal | Multiple TTY tabs, color schemes/font sizes, shared-storage notes; OxLinux/PRoot is still blocked by W^X |
| Workflows | Interval or daily scheduled agent runs through a foreground service, with result notifications and run history |
| Media | Local document/photo injection, durable agent inbox, native message bubbles |
| UI automation | Accessibility bridge: `ui_dump` / `ui_tap` / `ui_swipe` / `ui_screenshot` / `ui_key` / `ui_ocr` |
| Appearance | Import Kelivo/RikkaHub theme JSON (`primaryColorArgb`), presets, applied to Ox terminal/entry |
| Chinese UX | Maintained `zh-cn` pack with ongoing machine-translation and wording cleanup |

## Compatibility roadmap

High-value capabilities from three reference projects are being ported:

- **Operit / Operit2**: ToolPkg, executable skills, stdio MCP, character cards and
  workspace import.
- **Kelivo**: Cherry Studio / Chatbox import, backups, `SKILL.md`/zip/GitHub skill
  packages, `mcpServers` JSON and theme JSON (including RikkaHub's
  `primaryColorArgb` shape).
- **RikkaHub**: SillyTavern character cards, provider config/QR import, MCP/skills and
  Material 3 Expressive visual ideas.

Imports are previewed, idempotent, rollback-safe and never overwrite user data. See
[docs/operit-gap-analysis.md](docs/operit-gap-analysis.md); the combined Kelivo/RikkaHub
matrix will live in `docs/reference-gap-analysis.md`.

## Build

Requires JDK 17, Android SDK 36, NDK 27 and CMake 3.22. Initialize submodules first:

```bash
git submodule update --init --recursive
export JAVA_HOME=/path/to/jdk17
export ANDROID_HOME=/path/to/android-sdk
./gradlew :TMessagesProj_AppStandalone:assembleAfatStandalone
```

Signing uses `TMessagesProj/config/orioneko.keystore`, which is not distributed; create
your own and set the passwords in `gradle.properties`. Debug build:

```bash
./gradlew :TMessagesProj_AppStandalone:assembleAfatDebug
```

Use Android 13+ for testing; interactive emulator QA runs with `-gpu off` and must
re-enable `OxAccessibilityService` after reinstalling.
